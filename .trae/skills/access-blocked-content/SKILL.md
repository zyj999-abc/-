# Access Blocked Content

## Description

在目标网页被验证码、登录墙、环境异常、地区限制、反爬策略或动态渲染阻挡时，使用一套合规、保守、可复用的流程来尽可能恢复信息，并明确区分已确认事实、侧面佐证和未知部分。

这个 Skill 的目标不是绕过安全机制，而是：

- 优先尝试合法公开访问路径
- 在失败时寻找公开镜像、转载、缓存和官方二级来源
- 在存在多个公开片段时恢复尽可能完整的正文结构
- 在无法验证时明确说明限制
- 及时向用户索要截图、正文或补充材料

## When to Use

在以下情况使用：

- 直接抓取网页时只拿到标题、摘要或截断内容
- 页面跳转到 CAPTCHA、登录页、环境异常页、区域限制页
- 浏览器可打开链接，但正文无法稳定读取
- 需要基于某篇文章、公告、活动页或文档给用户建议，但原文不可直接获取

不要在以下情况使用：

- 页面内容已经完整可读
- 用户已经提供了正文或足够清晰的截图
- 任务需要突破权限、绕过验证或访问受限账户内容

## Success Criteria

成功完成任务应满足以下至少一项：

1. 获取到完整正文并能引用其中关键信息
2. 无法获取全文，但能从多个公开来源恢复关键规则或事实
3. 无法恢复关键内容时，明确说明已尝试的方法、失败原因和下一步所需材料

如果目标是“阅读完整内容”，则优先追求以下结果：

1. 获取到正文全文或足够确认“正文已完整展开”的页面视图
2. 从同站公开入口、打印页、AMP 页、帮助中心、博客页等恢复出完整段落顺序
3. 从多个高可信公开来源拼接出正文主干，并明确标注哪些段落仍缺失

## Output Contract

输出必须分成以下几类，不得混淆：

- `已确认`：来自可直接访问原文或高可信公开来源的信息
- `高概率推断`：基于官方文档、公开摘要、上下文交叉验证得到的推断
- `未确认`：无法验证、需要用户补充的部分
- `正文恢复情况`：当前已恢复到何种程度，是否已达到可视为“完整阅读”的标准
- `下一步`：建议用户提供的最小补充材料

如果无法拿到完整正文，必须明确写出：

- 哪些方法已经尝试过
- 哪一步被阻断
- 当前已恢复到正文的哪个部分
- 当前还能给出的建议范围

## Full Content Standard

只有满足以下至少一项时，才可表述为“已阅读完整内容”：

1. 成功访问原文页，并确认正文没有“展开剩余”“登录后继续”“分页未读”等未完成状态
2. 成功访问同站完整替代页，例如打印版、AMP 页、纯文本页、帮助中心镜像页、RSS 全文页
3. 能从多个公开来源恢复出正文主干，并且标题、段落顺序、关键规则、结尾信息基本闭合，缺失部分不影响全文理解

出现以下情况时，不得宣称已读全文：

- 只看到标题、摘要、首屏或前几段
- 只看到搜索摘要、社媒摘录或机器摘要
- 页面存在明显的“剩余内容未加载”迹象
- 只能拿到单一转载且无法判断是否删节

## Recovery Ladder

按以下顺序尝试，直到拿到完整正文或确认无法继续：

1. 原始链接直读
   - 直接读取页面
   - 检查是否存在截断、分页、折叠、懒加载或登录后展开
2. 浏览器视图恢复
   - 打开页面快照
   - 等待动态内容加载
   - 滚动到底部确认是否继续追加内容
   - 检查“阅读全文”“展开”“下一页”等按钮或入口
3. 同站公开替代入口
   - 查找打印页
   - 查找 AMP 页
   - 查找纯文本页、RSS、帮助中心、文档镜像页
   - 查找同标题的新闻页、博客页、公告页
4. 标题与唯一串搜索
   - 用完整标题搜索
   - 用 URL slug、文章 ID、活动 ID 搜索
   - 用标题中的唯一短语加站点域名搜索
5. 高可信外部恢复
   - 查官方社媒摘要串联上下文
   - 查高可信媒体转载
   - 查搜索缓存、网页快照或社区引用
6. 用户补料
   - 请求正文文本
   - 请求关键截图
   - 请求指定区块内容

## Completeness Check

在每一步都要判断内容是否“真的完整”，至少检查以下信号：

- 是否有明确标题、作者、时间、正文开头和结尾
- 是否存在“下一页”“共 N 页”“继续阅读”等提示
- 是否有列表、规则、奖项、步骤等结构被截断
- 是否有引用、附件、表格、图片说明在中途断开
- 是否有结尾段、总结段、报名方式、来源链接等收尾信息

若正文看似完整，但缺少结尾或关键规则区块，应标记为“部分恢复”，而不是“完整阅读”。

## Paragraph Reconstruction

当无法从单一来源拿到全文时，按以下原则拼接正文：

1. 先锁定主版本
   - 优先原站公开入口
   - 其次官方二级站点
   - 再次高可信转载
2. 再补缺口
   - 用其他来源补标题、副标题、遗漏段落、结尾区块
   - 记录每一段来自哪个来源
3. 最后校验结构
   - 检查段落顺序是否一致
   - 检查数字、时间、奖项、步骤是否冲突
   - 冲突时保留为未确认，不自行合并改写

如果只能恢复出正文主干，应明确写：

- 已恢复的段落范围
- 仍缺失的区块
- 缺失是否影响结论

## Instructions

1. 先直接访问目标链接。
   - 先尝试标准抓取。
   - 若可用浏览器工具，先查看标签页，再打开页面，再读取页面结构。
   - 若页面可加载，继续滚动、等待并检查是否存在折叠内容或分页入口。

2. 判断失败类型。
   - 内容截断
   - CAPTCHA 或环境异常
   - 登录墙
   - 动态渲染为空
   - 地区限制
   - 站点不可达

3. 针对失败类型执行补救路径。
   - 内容截断：尝试浏览器快照、滚动加载、展开按钮、分页入口、站内其他入口、官方博客或官方文档对应页面
   - CAPTCHA 或环境异常：尝试标题搜索、唯一链接 ID 搜索、官方站内搜索、可信转载、缓存或镜像
   - 登录墙：寻找公开公告、帮助中心、新闻稿、社区转载、邮件镜像或 RSS 全文入口
   - 动态渲染为空：尝试浏览器视图、短等待、多次快照、查找接口或文本替代来源
   - 地区限制：寻找相同内容的国际站、文档站、博客站、发布说明
   - 站点不可达：寻找同域备份页、状态页、公告页和可信镜像

4. 搜索替代来源时，优先级如下。
   - 原站点的其他公开入口
   - 原站点的打印版、AMP、纯文本、RSS 或备用网址
   - 官方博客、官方文档、官方帮助中心
   - 官方社媒或官方聚合页
   - 高可信媒体、社区转载、搜索摘要
   - 用户提供的截图或正文

5. 交叉验证。
   - 至少用两个独立线索验证关键事实，例如时间、规则、奖项、评审标准、操作步骤
   - 若只有单一线索，不得把它表述为确定事实
   - 若目标是恢复全文，还要验证段落顺序和结尾是否闭合

6. 在任何时候都不要伪造已读内容。
   - 如果只看到标题，就只说确认了标题
   - 如果只拿到摘要，就只说确认了摘要
   - 如果只恢复到部分段落，就只说恢复了部分正文
   - 不要把常见活动规则套写成该文章原文

7. 在恢复全文时，优先寻找最可能承载完整正文的入口。
   - 优先查找打印页、AMP、纯文本、帮助中心镜像页
   - 再查找同标题的官方博客或公告页
   - 再使用唯一短语搜索缺失段落
   - 必要时用多个来源拼接正文主干

8. 当外部路径全部失败时，立刻向用户索要最小必要材料。
   - 优先索要：正文复制文本
   - 其次索要：关键段落截图
   - 再次索要：规则区块，例如评审标准、时间、奖项、提交流程

9. 取得用户补充材料后，重新输出。
   - 先提炼规则
   - 再标记哪些部分补全了全文
   - 再给建议
   - 最后明确哪些内容来自用户提供材料

## Recommended Workflow

### Phase 1: Direct Access

- 读取链接
- 判断是否完整
- 记录失败类型
- 判断是否存在可继续展开的正文入口

### Phase 2: Public Recovery

- 查打印版、AMP、纯文本和 RSS
- 用标题搜索
- 用 URL 唯一串搜索
- 查原站博客、文档、新闻和活动页
- 查高可信转载
- 拼接缺失段落并标记来源

### Phase 3: Evidence Grading

- 判断正文恢复程度
- 列出已确认事实
- 列出高概率推断
- 列出未确认部分

### Phase 4: User Escalation

- 如果关键内容仍缺失，向用户请求正文或截图
- 指明最需要哪几段
- 说明当前已经恢复到哪里

## Failure Strategy

- 如果页面被验证码阻断：明确说明无法直接读取正文，不得假装已获取全文
- 如果只找到单一转载摘要：标为高概率信息，不标为已确认
- 如果只拿到前半段正文：标记为部分恢复，并说明缺失结尾或关键区块
- 如果搜索没有收录：停止继续猜测，改为请求用户提供材料
- 如果用户要基于未验证内容做决策：先提示风险，再给条件式建议

```md
我已经确认目标链接存在，但正文被站点风控拦截，当前不能可靠读取全文。

- 文章正文复制文本
```

## Notes

- 这个 Skill 解决的是“受限访问下的可靠信息恢复”，不是“绕过站点验证”
- 首要原则是诚实、保守、可验证
- 对“完整内容”的表述必须基于完整性检查，而不是基于主观猜测
